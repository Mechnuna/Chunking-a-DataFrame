# Chunking a DataFrame by a non-splittable column
Необходимо реализовать функцию, которая будет:

- оптимально расходовать память
- возвращать фрейм, разбитый по конкретной серии на чанки желаемого размера
- размер возвращаемых чанков должен быть больше или равен желаемому
- даты между чанками пересекаться не должны

## Структура репозитория

```
.
├── solution.py                  # базовое решение: сортированные данные, помещаются в память
├── solution_external.py         # данные НЕ отсортированы и НЕ помещаются в память целиком
├── test_solution.py             # тесты для solution.py
├── test_solution_unsorted.py    # тесты для sort-helper'а и out-of-core варианта
└── README.md
```

### `solution.py` — базовый случай

```python
from solution import iter_chunks_by_column

for chunk in iter_chunks_by_column(df, "dt", chunk_size=4):
    ...  # обрабатываем чанк, не держа остальные в памяти
```

Это генератор, выполняющий один линейный проход по уже отсортированной
колонке: соседние группы одинаковых значений накапливаются, пока их
суммарный размер не достигнет `chunk_size`, после чего накопленное
отдаётся как очередной чанк.

Если отсортированность колонки не гарантирована, функция по умолчанию
сама это проверит (`series.is_monotonic_increasing`) и кинет `ValueError`.

Там же — `sort_by_column_for_chunking(df, column)`: если данные **не отсортированы, но помещаются в память**.

### `solution_external.py` — датафрейм не отсортирован и не помещается в память

Если данные физически не влезают в RAM, однопроходный стриминг
невозможен в принципе (при несортированных данных нельзя закрыть чанк,
не увидев вообще все вхождения текущего значения). Решение —
двухпроходное партиционирование без полной сортировки:

1. **Проход 1** (потоковое чтение батчами) — считаем количество строк на
   каждое уникальное значение колонки. Память ~ O(число уникальных
   значений), а не O(число строк).
2. На этих маленьких агрегатах жадно определяем, какому чанку
   принадлежит каждое уникальное значение.
3. **Проход 2** (снова потоково) — раскладываем строки по файлам на диске
   согласно этому распределению. Память ~ O(число открытых файлов).

```python
from solution_external import iter_chunks_external

def batches():
    return pd.read_csv("huge_unsorted.csv", chunksize=200_000)

for chunk_path in iter_chunks_external(batches, "dt", chunk_size=100_000):
    ...  # чанк лежит на диске, читаем и обрабатываем по одному
```

## Запуск тестов

```bash
pip install -r requirements.txt
pytest -v
```

26 тестов, покрывающих:

- все три кейса из условия задачи (1–2 / 3–5 / ≥6) и граничный случай
  "хвостовой чанк меньше желаемого размера";
- неразрывность групп одинаковых значений, в том числе при `chunk_size=1`;
- отсутствие пересечений между чанками и полное покрытие исходных данных;
- пустой датафрейм, некорректный `chunk_size`, отсутствующую колонку;
- несортированную колонку (отказ по умолчанию / явное разрешение);
- то, что решение действительно генератор, а не накапливающий список;
- сортировку-помощник для случая "не отсортировано, но влезает в память";
- двухпроходное внешнее партиционирование для случая "не отсортировано и
  не влезает в память" — на синтетических батчах.
